# 序：这本书要回答什么

Kubernetes 的调度与运维抽象，是为**无状态负载**设计的。它管理 Pod、节点和资源对象，用 readiness 探针判断"能不能用"，用 PDB 判断"一次能停几个"，用 reconciliation 收敛到期望状态。

数据库和分布式中间件不是这么工作的。它们维护的是**角色关系、成员集合和协议不变式**：谁是 primary、谁有投票权、成员集合是否满足 quorum、成员变更是否串行。这些概念在 Kubernetes 的对象模型里没有对应物。

于是出现了这样的错位：每一个动作单独看都合规——"一次只重启一个 Pod"满足 PDB，"单个节点排空"满足驱逐条件——叠在一起却击穿了 quorum。问题不在某个参数配错了，而在于**控制面看不见数据库的语义**。

这本书试图把这类问题系统讲清楚：先固定问题与约束，再看 Kubernetes 原生提供了什么、缺什么，然后沿"**观测 → 准入 → 编排 → 协议保证**"这条线梳理可行解法，并逐条标明能力边界。全书以 KubeBlocks 作为主要参照实现。
